# 生成 Agent Stack README

根据仓库已经维护的公开事实生成一份可直接使用的完整 Markdown 文档。默认写入仓库根目录的 `README.md`；用户指定其他路径时，只写入该路径并保持 README 不变。

只使用当前环境的通用文件读取、搜索和编辑能力。不要执行仓库 `scripts/` 下的程序，不要创建或运行 Shell、Python 或其他辅助程序。

## 确认边界

先检查工作树，保护用户已有变更。只读取以下事实来源：

1. 仓库级 `AGENTS.md`：确定仓库定位、统计口径与敏感信息边界。
2. `snapshot/*.json`：确定已经公开的名称、来源、版本、状态和哈希语义。
3. `snapshot/catalog.json`：确定稳定的分组、用途和展示名称。
4. 现有 `README.md`：保留仍然有效的解释、链接、顺序与结构。

不要盘点实时环境，不要读取本机配置补充新事实，不要更新 `snapshot/`。如果用户要求反映当前本机状态，而结构化快照明显过期，停止生成并提示先完成仓库独立的快照维护流程。

## 组织内容

围绕“仓库是什么、公开了什么、如何理解、如何维护”组织 README。优先沿用以下结构：

1. 标题、仓库定位和快照摘要。
2. 状态边界与环境结构。
3. 按场景分组的 Skills。
4. 显式启用与仅缓存的 Codex 插件。
5. MCP 服务及其非敏感用途。
6. 本地工具链概览与高价值使用说明。
7. 全局工作规范摘要、完整副本和来源哈希。
8. 仓库级快照维护说明。

保持标题层级连续且唯一。重复字段使用表格，边界说明使用短段落或列表，长副本放入 `<details>`。保留未变化条目的措辞和顺序，不为了视觉变化重排内容。

## 生成文档

使用自然、准确、紧凑的中文。保留命令、路径、标识符和产品名称的原始形式。每个用途说明只表达一个核心能力，不添加宣传语、模板化前言或无证据评价。

只输出公开信息：

- 将主目录路径写成 `~/...`，不要写绝对用户目录。
- 不要写令牌、凭据、私钥、环境变量值、命令参数或带参数的服务地址。
- 不要从第三方 Skill 或插件的自由文本说明推导新事实。
- 不要混淆本机缓存、配置登记、明确启用和当前会话暴露。
- 不要把 README 生成描述成快照盘点或更新机制。

一次性写出完整文档。用户要求候选稿或指定输出文件时，只创建该文件；不要顺带修改 README、快照、安装状态或其他文档。

## 验证成品

重新阅读成品并确认：

- 标题层级、表格列数、代码围栏和 HTML 折叠区块正确配对。
- 数量、版本、状态、来源和哈希与结构化快照一致。
- 本地链接有效，远程链接只保留已有且必要的公开来源。
- 不含绝对主目录、敏感配置值、重复章节或无关格式化。
- 除目标文件外没有其他文件被本次生成修改。

最后报告输出路径、文档结构、采用的事实来源、检查结果和仍无法确认的内容。
